# Desktop Vocabulary Coach

## 产品需求与技术设计文档（供 OpenCode 实施）

-   文档版本：1.0
-   项目代号：Desktop Vocabulary Coach
-   目标平台：Windows 10 / Windows 11 x64
-   首选技术栈：.NET 10 LTS + WPF + SQLite
-   产品定位：常驻后台、低干扰、间歇式推送英语单词的桌面学习工具

------------------------------------------------------------------------

## 1. 项目目标

开发一个 Windows
桌面英语学习工具。应用启动后可最小化到系统托盘，在后台根据用户状态和学习计划，间隔一段时间显示一个轻量的桌面浮动单词卡片。用户可以快速反馈对单词的掌握程度，系统据此安排后续复习，并逐步调整推荐难度。

产品核心不是完整的课程或词典，而是把碎片时间转化为低负担的单词接触与记忆复习。

### 1.1 核心体验

1.  应用启动后常驻系统托盘，不要求主窗口一直打开。
2.  在适合的时机随机弹出一个单词卡片，而不是固定整点提醒。
3.  卡片默认先展示单词和音标；用户主动展开后查看释义、例句等内容。
4.  用户通过"认识 / 模糊 / 不认识"快速反馈。
5.  系统结合新词推荐和遗忘复习，持续调整后续推荐。
6.  核心学习功能完全离线可用；AI 仅作为可选增强能力。

### 1.2 本期明确不做

-   不做账号体系、云同步和社交功能。
-   不做在线课程、考试系统或复杂词典。
-   不把 AI 设为运行前提。
-   不在用户全屏游戏、演示、会议或长时间离开电脑时强行弹窗。
-   不以关闭弹窗作为"认识"或"已掌握"的依据。

## 2. 产品默认配置

以下作为第一版默认值，均应在设置中允许用户调整。

  配置项          默认值         说明
  --------------- -------------- ----------------------------------
  推荐模式        Smart          新词与到期复习混合推荐
  弹出频率        Random         随机间隔，不固定整点
  随机间隔        12--35 分钟    在允许弹出的工作时段内随机抽取
  每小时上限      4 次           防止打扰过多
  勿扰时间        22:30--08:00   勿扰时段不弹出
  难度模式        Adaptive       根据反馈自动调整
  卡片样式        Floating       桌面浮动卡片
  AI              Optional       默认关闭或未配置时不影响核心功能
  新词/复习倾向   约 60% / 40%   仅作为目标倾向；逾期复习优先
  空闲检测        启用           用户离开电脑时不弹出
  全屏检测        启用           全屏应用期间不弹出

### 2.1 推荐规则优先级

从高到低：

1.  用户处于勿扰时间、全屏应用、锁屏或空闲状态：不弹出。
2.  存在到期或逾期复习词：优先考虑复习。
3.  复习队列压力较低时，按新词/复习目标比例混合推荐。
4.  新词优先选择符合当前水平、实用性较高且尚未学习的词。
5.  最近连续出现"不认识"或"模糊"时，适当降低新词难度或增加复习比例。

不要为了严格达到 60/40 比例而跳过已经逾期的复习任务。

## 3. 用户流程与交互

### 3.1 首次启动

1.  启动应用，显示简洁的首次配置向导。
2.  用户选择或确认英语水平；提供"暂不确定，使用自适应"选项。
3.  用户确认弹窗频率、勿扰时段。
4.  初始化本地 SQLite 数据库和内置词库。
5.  应用进入系统托盘常驻状态。
6.  首次启动可提供"立即测试弹窗"入口。

### 3.2 日常学习流程

1.  后台调度器等待随机间隔。
2.  调度器检查系统状态和勿扰规则。
3.  推荐引擎选择一个新词或复习词。
4.  显示桌面浮动卡片。
5.  用户查看单词，可点击展开释义、例句和发音。
6.  用户选择"认识""模糊"或"不认识"。
7.  保存反馈和复习记录，更新下次复习时间。
8.  卡片关闭，重新安排下一次弹出时间。

### 3.3 浮动卡片布局

默认卡片建议宽约 340--400
DIP，高度随内容变化，显示在主屏幕右下角，距离屏幕边缘留出安全间距。

**折叠状态：**

-   单词
-   音标
-   发音按钮
-   "查看释义"按钮
-   关闭按钮

**展开状态：**

-   单词、音标、词性
-   核心中文释义
-   一条简短英文例句及中文翻译
-   发音按钮
-   反馈按钮：认识 / 模糊 / 不认识
-   稍后提醒（可选）

交互要求：

-   窗口无边框、置顶、可拖动。
-   不抢夺键盘焦点；尽量不影响当前输入。
-   支持淡入淡出动画，但动画应短且可关闭。
-   用户点击关闭只记录为 dismissed，不更新掌握状态。
-   显示期间不重复弹出其他卡片。
-   支持屏幕 DPI 缩放和多显示器环境。

### 3.4 系统托盘菜单

至少包含：

-   显示主窗口
-   暂停提醒 30 分钟
-   暂停提醒 1 小时
-   暂停提醒至明天
-   立即弹出一个单词（测试/手动学习）
-   今日学习统计
-   设置
-   退出

退出必须真正停止后台调度器并释放数据库连接。

## 5. 后台调度设计

### 5.1 调度流程

``` text
启动
  |
加载设置与学习状态
  |
生成随机等待时间（12–35 分钟）
  |
等待或响应暂停/退出信号
  |
检查勿扰时间
  |
检查锁屏、空闲、全屏状态
  |
是否允许弹出？ -- 否 --> 延迟后重新检查
  |
选择复习词或新词
  |
显示浮动卡片
  |
等待用户反馈或超时关闭
  |
保存事件与学习进度
  |
安排下一轮
```

### 5.2 系统状态检测

通过 Windows API 封装系统状态检测，避免将 P/Invoke 散落在业务代码中。

-   `GetLastInputInfo`：计算用户距上次键鼠输入的空闲时长。
-   `GetForegroundWindow`：获取前台窗口。
-   `GetWindowThreadProcessId`：获取前台窗口所属进程。
-   `GetSystemMetrics` 或合适的窗口信息 API：辅助判断显示环境。
-   锁屏检测可通过会话通知或可靠的 Windows 会话状态 API 实现。

第一版建议规则：

-   空闲超过 3 分钟：不弹出。
-   检测到全屏窗口：不弹出。
-   锁屏或用户会话断开：不弹出。
-   从不允许状态恢复后，不要立即连续补弹多个单词；重新进入随机调度。
-   检测失败时采用保守策略：暂缓弹出，并记录日志。

全屏检测在多显示器、无边框全屏和 DPI
环境下可能存在边界情况，需单独测试。

### 5.3 调度伪代码

``` csharp
while (!stoppingToken.IsCancellationRequested)
{
    var delay = random.Next(settings.MinIntervalMinutes,
                            settings.MaxIntervalMinutes + 1);

    await Task.Delay(TimeSpan.FromMinutes(delay), stoppingToken);

    if (pauseState.IsPaused)
        continue;

    if (!quietHours.IsAllowed(DateTimeOffset.Now))
        continue;

    var systemState = await systemStateMonitor.GetStateAsync(stoppingToken);

    if (!systemState.IsEligibleForPopup)
        continue;

    if (rateLimiter.HasReachedHourlyLimit())
        continue;

    var recommendation = await recommendationService
        .GetNextWordAsync(stoppingToken);

    if (recommendation is null)
        continue;

    await popupPresenter.ShowAsync(recommendation, stoppingToken);
}
```

这是流程示意。生产实现应正确处理暂停期间的等待、应用退出、用户反馈超时、弹窗正在显示和系统时间变化等情况。不要使用
`Thread.Sleep` 阻塞线程。

## 6. 单词推荐与自适应难度

### 6.1 推荐模式

Smart 模式下综合考虑：

-   到期复习任务
-   新词/复习比例
-   用户当前难度水平
-   单词常见程度和实用性
-   最近学习记录
-   连续失败情况
-   用户手动标记的熟悉/不熟悉状态

第一版可使用可解释的规则评分，不需要机器学习模型。

建议评分因素：

``` text
复习优先级 = 逾期程度权重 + 遗忘风险权重 + 失败次数权重

新词优先级 = 词频权重 + 水平匹配权重 + 实用性权重
             - 难度偏离惩罚 - 最近重复惩罚
```

所有权重集中在配置或策略类中，不要散落在 UI 代码里。

### 6.2 自适应难度

用户选择"认识 / 模糊 / 不认识"后，更新最近 20 次有效反馈统计。

建议初始策略：

-   最近 20 次中"认识"比例高于 80%，且" 不认识"低于
    10%：逐步提高新词难度。
-   "不认识"比例高于 35%：降低新词难度，增加复习倾向。
-   其他情况：保持当前难度。
-   每次调整只移动一个小档位，避免频繁跳变。

以上比例是初始产品参数，后续应根据实际体验调整。关闭弹窗、稍后提醒和超时不计入有效掌握反馈。

### 6.3 反馈语义

  用户操作   业务含义         复习处理
  ---------- ---------------- ----------------
  认识       当前回忆成功     拉长间隔
  模糊       有印象但不牢固   短间隔复习
  不认识     当前未能回忆     尽快再次学习
  关闭       用户未提供反馈   不判定掌握
  稍后提醒   延迟本次展示     不更新掌握状态

### 6.4 复习算法

设计 `IReviewScheduler` 接口，隔离具体算法。

``` csharp
public interface IReviewScheduler
{
    ReviewScheduleResult Schedule(ReviewState state, ReviewRating rating,
                                  DateTimeOffset reviewedAt);
}
```

优先评估 FSRS 算法；如果第一版缺少成熟、兼容的 .NET 实现，可以先实现简化
SM-2，并保留后续替换能力。

不要把复习间隔逻辑写进 ViewModel 或数据库 Repository。

## 7. 数据库设计

使用 SQLite，数据库文件放在用户本地应用数据目录，例如：

`%LocalAppData%/DesktopVocabularyCoach/vocabulary.db`

不要把数据库放在程序安装目录。

### 7.1 核心表

#### Words

  字段             类型           说明
  ---------------- -------------- --------------------------
  Id               INTEGER PK     主键
  Word             TEXT           单词原文
  NormalizedWord   TEXT           规范化单词，唯一索引
  Phonetic         TEXT NULL      音标
  Difficulty       INTEGER        难度等级
  FrequencyRank    INTEGER NULL   词频排名，数值越小越常见
  Source           TEXT           词库来源
  CreatedAt        TEXT           创建时间

#### WordDefinitions

  字段           类型         说明
  -------------- ------------ ------------
  Id             INTEGER PK   主键
  WordId         INTEGER FK   关联 Words
  PartOfSpeech   TEXT NULL    词性
  DefinitionZh   TEXT         中文释义
  DefinitionEn   TEXT NULL    英文释义
  ExampleEn      TEXT NULL    英文例句
  ExampleZh      TEXT NULL    例句翻译

一个单词允许有多个释义。

#### UserWordProgress

  字段             类型         说明
  ---------------- ------------ ---------------------------------------
  Id               INTEGER PK   主键
  WordId           INTEGER FK   单词
  Status           INTEGER      New / Learning / Review / Mastered
  Repetition       INTEGER      连续成功次数或算法状态
  EaseFactor       REAL         SM-2 参数；若使用 FSRS 可扩展状态字段
  IntervalDays     REAL         当前复习间隔
  DueAt            TEXT NULL    下次复习时间
  LastReviewedAt   TEXT NULL    最近复习时间
  LapseCount       INTEGER      遗忘/失败次数
  UpdatedAt        TEXT         更新时间

`WordId` 应建立唯一约束，避免同一用户进度重复。

#### ReviewLogs

  字段            类型         说明
  --------------- ------------ --------------------------------
  Id              INTEGER PK   主键
  WordId          INTEGER FK   单词
  Rating          INTEGER      Again / Hard / Good 等内部评分
  UserFeedback    INTEGER      Recognized / Vague / Unknown
  ReviewedAt      TEXT         反馈时间
  PreviousDueAt   TEXT NULL    原到期时间
  NextDueAt       TEXT NULL    新到期时间
  Source          TEXT         Popup / Manual / Test

#### LearningSessions

记录每次展示和学习行为，包括：

-   Id
-   WordId
-   ShownAt
-   RespondedAt
-   Action
-   DurationMs
-   Source

Action 至少支持
Recognized、Vague、Unknown、Dismissed、Snoozed、Timeout。

#### UserLearningProfile

保存用户当前难度、水平估计、最近反馈统计和自适应参数。

#### AppSettings

保存键值型设置，或使用强类型配置表。设置项至少包含弹出频率、随机间隔、勿扰时间、每小时上限、空闲阈值、全屏检测开关、AI
开关、主题等。

#### AiGenerationCache

缓存 AI 生成的释义、例句等内容，避免重复请求。AI
关闭时不得影响本地词库查询。

### 7.2 数据约束与迁移

-   使用 EF Core Migration 管理结构变更。
-   为 `NormalizedWord`、`DueAt`、`WordId` 等常用查询字段建立索引。
-   所有时间统一存储
    UTC，展示时转换为本地时间；勿扰时间按用户本地时区计算。
-   对用户反馈、复习记录采用事务保存。
-   应用升级时保留已有用户数据。
-   提供数据库备份和恢复入口，至少支持手动复制数据库文件。

## 8. 词库与内容

### 8.1 第一版词库

优先使用可合法再分发的公开词库或自行整理的词表。必须在仓库中保留词库来源、许可证和署名要求。

建议先导入一批规模适中的常用词（例如 3,000--5,000
个），验证推荐和复习闭环，再扩展词库。

词条至少包含：

-   单词
-   音标（如有）
-   难度等级
-   词频或常用程度
-   中文释义
-   词性
-   简短例句（如有）

不要抓取或打包来源不明、许可证不明确的商业词典数据。

### 8.2 导入机制

实现可重复执行的词库导入器：

-   支持 CSV 或 JSON。
-   根据 NormalizedWord 去重。
-   支持新增和更新，不覆盖用户学习进度。
-   导入失败输出可读错误日志。
-   提供导入统计：新增、更新、跳过、失败。

## 9. AI 可选增强

AI 必须是可插拔能力。未配置 API
Key、网络不可用或请求失败时，应用仍可完整使用本地词库。

建议抽象：

``` csharp
public interface IVocabularyEnrichmentProvider
{
    Task<EnrichedWord?> EnrichAsync(string word,
                                    CancellationToken cancellationToken);
}
```

第一版 AI 功能范围：

-   根据目标水平生成更贴近用户的例句。
-   对释义进行简明解释。
-   为容易混淆的词提供差异说明。

约束：

-   不在每次弹窗时实时调用 AI。
-   通过缓存减少重复请求。
-   请求设置超时、取消和失败降级。
-   API Key 使用 Windows DPAPI
    或其他适合本机的安全存储方式，不明文写入配置文件或日志。
-   不把用户学习记录上传给 AI，除非未来明确设计并获得用户授权。
-   第一阶段可只实现接口和 Mock Provider，真实 AI 接入放到后续 Sprint。

## 11. 稳定性、性能与隐私

-   应用常驻时应保持低 CPU、低内存占用。
-   调度等待不得使用忙循环。
-   所有后台任务支持 CancellationToken。
-   数据库操作使用异步 API。
-   关键异常写入滚动日志文件，不记录 API Key。
-   单词学习数据默认只保存在本机。
-   应用崩溃后重新启动，不应丢失已经提交的反馈。
-   同一时刻最多显示一张学习卡片。
-   关闭主窗口默认最小化到托盘；从托盘菜单退出才真正退出。
-   安装、升级和卸载不得误删用户数据库；卸载是否保留数据应明确告知用户。

## 12. 开发里程碑

采用小步交付。每个 Sprint 都必须有可运行版本和验收结果。

### Sprint 1：桌面应用骨架与托盘

任务：

1.  创建 .NET 10 WPF 解决方案。
2.  建立 Core / Application / Infrastructure / App 项目。
3.  配置 Generic Host、DI、日志和配置。
4.  实现主窗口、关闭到托盘、托盘菜单。
5.  实现一个可手动触发的浮动卡片。
6.  建立基本单元测试工程。

验收：

-   应用可以正常启动和退出。
-   关闭主窗口后应用仍在托盘运行。
-   可以从托盘重新打开主窗口。
-   可以手动弹出和关闭单词卡片。
-   后台服务退出时能正确释放资源。

### Sprint 2：SQLite 与本地词库

任务：

1.  建立 EF Core SQLite 数据层。
2.  建立核心实体和 Migration。
3.  实现词库 CSV/JSON 导入。
4.  导入首批合法词库数据。
5.  实现按单词查询和释义展示。

验收：

-   首次启动自动创建数据库。
-   重启后数据仍存在。
-   重复导入不会产生重复单词。
-   用户进度不会被词库更新覆盖。

### Sprint 3：随机后台调度

任务：

1.  实现随机间隔调度器。
2.  实现勿扰时段。
3.  实现每小时弹出上限。
4.  实现空闲状态检测。
5.  实现全屏状态检测。
6.  实现暂停与恢复。

验收：

-   在测试配置下可缩短间隔快速验证。
-   非允许状态下不弹出。
-   允许状态恢复后不会连续补弹。
-   暂停和退出可以及时取消等待。

### Sprint 4：反馈与复习闭环

任务：

1.  实现认识 / 模糊 / 不认识反馈。
2.  实现 ReviewLogs 和 LearningSessions 写入。
3.  实现 `IReviewScheduler`。
4.  实现初版 SM-2 或经验证的 FSRS 封装。
5.  实现到期复习优先推荐。

验收：

-   三种反馈均能正确更新进度。
-   关闭弹窗不会被记为认识。
-   复习时间计算有单元测试覆盖。
-   逾期复习优先于普通新词。

### Sprint 5：自适应与产品设置

任务：

1.  实现最近 20 次反馈统计。
2.  实现难度自适应规则。
3.  实现提醒、学习、显示设置。
4.  实现今日学习统计。
5.  完善异常日志和数据备份。

验收：

-   用户反馈能影响后续难度。
-   用户可调整提醒和勿扰设置。
-   设置重启后仍然生效。
-   统计数据与学习日志一致。

### Sprint 6：AI 增强与发布准备

任务：

1.  实现 AI Provider 抽象和 Mock Provider。
2.  实现可选 OpenAI-compatible Provider。
3.  实现 AI 结果缓存和失败降级。
4.  完善安装包、版本信息和首次启动体验。
5.  完成多显示器、DPI、长时间运行测试。

验收：

-   AI 关闭时所有核心功能正常。
-   AI 失败时回退到本地词库。
-   API Key 不明文落盘或进入日志。
-   安装、升级和卸载流程可验证。

## 13. MVP 范围与优先级

第一阶段只要求完成以下闭环：

1.  Windows 后台托盘常驻。
2.  可手动触发浮动单词卡片。
3.  后台按随机间隔弹出单词。
4.  基础勿扰、空闲和全屏保护。
5.  用户可以反馈认识 / 模糊 / 不认识。
6.  SQLite 保存反馈和学习进度。
7.  能够根据反馈安排下一次复习。

**第一阶段不要求 AI、自适应算法、复杂统计或精美动画。**

优先保证后台稳定、弹出时机合理、反馈数据可靠。功能扩展必须建立在这一闭环可用的基础上。
